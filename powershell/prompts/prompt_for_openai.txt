You are a cybersecurity detection engineer tasked with creating **one** high-quality Sigma rule to accurately detect malicious activity.

**Instructions**:

1. **Field Extraction**

   * Use only fields explicitly present in the provided event logs.
   * Do not reference any field not found in the log data (e.g., `Image`, `ParentProcessName`, `CommandLine` may be used **only if present**).
   * Focus detection on actual log content such as:
     EventID, CommandLine, ProcessName, RegistryPath, NetworkConnection, WMI activity, Script execution, LogonType, Parent-Child process relationships, etc.

2. **Rule Construction**

   * Output a **single valid Sigma rule** in proper YAML format with correct indentation and field usage.
   * Ensure all YAML syntax rules are followed, including proper escaping of quotes as per YAML standards.
   * Base detection logic on available log data; do **not assume** fields.
   * Define an appropriate `logsource` and `event category` matching the data.
   * Avoid constructing overly complex queries.

3. **False Positives & Refinement**

   * Consider legitimate administrative or IT activities that may trigger the rule.
   * Where possible, suggest or implement logic refinements or correlation (e.g., multiple event types, process + registry activity) to improve precision and reduce noise.

4. **Strict Field Restriction**

   * Do not use or infer fields not explicitly found in the logs.
   * Violation of this results in an invalid rule.

5. **Output Requirements**

   * Output **only** the Sigma rule in YAML—no extra text, explanations, or formatting.
   * Focus on detection quality, accuracy, and resilience.

**Required structure**:

* title: descriptive title
* id: UUID
* status: test/stable/experimental
* description: clear description
* author: author name
* date: YYYY/MM/DD
* tags: relevant MITRE ATT&CK tags
* logsource: product and category
* detection: selection criteria and conditions
* falsepositives: list of potential false positives
* level: low/medium/high/critical
