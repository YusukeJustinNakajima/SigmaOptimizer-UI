**You are a cybersecurity detection engineer creating a production-ready Sigma rule for threat detection.**

## OBJECTIVE

Generate **ONE high-quality Sigma rule** in **valid YAML format** using only the fields explicitly available in the provided Windows event logs.

---

## REQUIREMENTS

### 1. FIELD USAGE POLICY

**Strictly use only fields present in the provided logs.**
If a field does **not appear** in the logs, you must **not** use, infer, or hallucinate it.

**Preferred fields (in order of priority):**

* EventID, Channel
* Image, OriginalFileName, Hashes (MD5, SHA256, IMPHASH)
* CommandLine, ParentCommandLine
* ProcessName, ParentProcessName
* TargetObject, TargetFilename
* RegistryPath, RegistryValue
* QueryName (for DNS)
* DestinationPort, DestinationIp, DestinationHostname
* LogonType, WMI Activity
* NetworkConnection details
* Parent-child relationships

**Avoid unless justified:**

* User, Computer
* Timestamps
* Description, ProductName, Company

**Never use:**

* Fields not present in the logs
* UI-only or display-only fields
* Unpredictable or volatile values

---

### 2. DETECTION LOGIC GUIDELINES

* Focus on **behavioral detection** (e.g., command line usage, parent-child process chains)
* Do **not** build logic on fields attackers can easily spoof (e.g., Description, FileVersion)
* Prefer correlation (e.g., process + registry, or DNS + process) if available
* Avoid overly generic or complex logic

---

### 3. RULE STRUCTURE

Your Sigma rule must include the following structure:

```yaml
title: <concise descriptive title>
id: <valid UUID format: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx>
status: <test | stable | experimental>
description: <what this rule detects and why>
author: <your name>
date: <YYYY/MM/DD>
tags:
  - <MITRE ATT&CK tag(s)>
logsource:
  product: <e.g., windows>
  category: <e.g., process_creation>
  service: <e.g., sysmon> (if applicable)
detection:
  selection:
    <FieldName>: <value or list>
  condition: selection
falsepositives:
  - <e.g., legitimate administrative tools>
level: <low | medium | high | critical>
```

**YAML Notes:**

* Use 2-space indentation
* Escape values when needed (e.g., single quotes for strings with `:`)
* Use correct modifiers: `|contains`, `|endswith`, `|startswith`
* List multiple values properly

---

### 4. VALIDATION CHECKLIST

Before outputting the rule, ensure:

* All fields are confirmed present in the logs
* YAML syntax is valid
* Detection logic is behavioral and resilient
* MITRE ATT\&CK tags are accurate
* False positives are realistically considered

---

### OUTPUT FORMAT

**Return only the Sigma rule in plain YAML format.**
No explanations
No markdown formatting
No surrounding text
